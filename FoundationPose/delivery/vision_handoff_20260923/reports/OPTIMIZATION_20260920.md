# RTX 4070 YOLOv8-seg + FoundationPose 优化复测

测试入口：`my_demo/scripts/benchmark_registration.py --start-camera --duration 35 --target-class 0 --resets 2`。测试使用本机 D435i 327122073383、1280x720@30 采集、15 Hz 发布、压缩 RGB-D，输出只发布到私有话题 `/sb_metrics_test/object_pose`，没有控制机器人。

本次实现将生产节点的 YOLO 刷新频率默认设为 10 Hz，FoundationPose 仍处理每个 RGB-D 帧；短暂漏检复用当前目标关联，连续漏检超过 0.30 s 才清除种子；相机短暂断帧恢复时优先尝试已有位姿种子跟踪；模型在首帧前预加载。

实测结果：

| 指标 | 结果 |
|---|---:|
| 连续运行时间 | 38.20 s |
| 有效 ObjectPose | 507 条 |
| 有效输出频率 | 约 13.3 Hz |
| 初次注册耗时 | 233.4 ms |
| 重注册耗时 | P50 129.6 ms，P95 135.6 ms |
| 跟踪耗时 | P50 19.2 ms，P95 24.7 ms |
| 手动 reset 恢复 | 0.266 s、0.276 s |
| 首次有效输出 | 4.135 s（包含 3.179 s 模型预加载） |
| YOLO 刷新 | 约 10 Hz；FoundationPose 跟踪约 15 Hz |
| NVML 进程显存峰值 | 1.43 GiB |

作为同一相机、同一类别的旧生产记录参照，旧模式在 818 个处理帧上调用 YOLO 818 次；优化后 510 个处理帧调用 258 次，YOLO 调用比例约下降 68%。旧模式跟踪 P50/P95 为 29.5/41.6 ms，优化后为 19.2/24.7 ms。该差异同时受运行场景和 GPU 负载影响，不能单独解释为模型精度提升；质量门和目标尺寸参数保持不变。

完整原始数据在本目录的 `summary.json`、`events.jsonl` 和 `run_report.json`。145 项本地回归测试全部通过。

需要区分两种时间：进程第一次启动的 3～4 s 主要是模型加载；进程已运行后的目标恢复主要由目标重选等待和注册组成。默认保留 1 s 的重新选目标等待以避免多瓶场景误切换；若下游已锁定目标，可显式使用 `--reselect-after-seconds 0.3` 做更快恢复，并应在实物遮挡测试后再用于抓取。
